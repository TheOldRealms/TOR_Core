TpacTool.IO.dll is unmodified; the Release build from the same tag works as-is.

Why the patch exists: upstream AssetPackage.Load relies on a
[Conditional("DEBUG")] assertion to notice when ReadMetadata under-reads an
asset's metadata block. Release builds strip that assertion, so a short
read silently drifts the stream and every subsequent asset is parsed from
the wrong offset — producing an EndOfStreamException partway through load.
Newer Bannerlord releases append trailing fields to per-asset metadata
that this parser doesn't understand; the patch trusts the authored
metadataSize field and seeks past the unknown trailing bytes.
